# 2026-04-27 内容创作目标与修改方向拆分

## 背景

创建任务流程中，第 2 步“目标和范围确认”和第 3 步“修改策略确认”在文案上过于接近，用户容易误以为两个页面都在问“怎么改”。

## 改动

1. 第 2 步收窄为“工作目标和处理范围”，只确认最终产品类型和本轮处理章节。
2. 第 2 步候选项从“多人演播有声书 · 先做业务分析”改为“多人演播有声书”等产品目标，避免把分析阶段写进目标名。
3. 第 3 步改为“修改方向确认”，承接业务分析 Agent 的问题证据，再决定改法深度、交付清单和制作 Agent。
4. 补充 UI 规范：`task.intake_planner@1.0` 只产出目标订单和范围，业务分析 Agent 才产出修改方向。

## 验证

1. `npx tsc --noEmit`
2. `npm run build`
