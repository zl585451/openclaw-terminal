# 2026-04-02 MiniMax 流式中断修复

## 问题描述

用户报告 MiniMax 模型回复时出现流式中断，导致对话断开。日志显示：
- `[WARN] stream interrupted {"outputLen":0}`
- 第一次请求正常，后续请求立即失败

## 根因分析

1. **代理配置错误**：`getDirectFetchOptions()` 函数对所有 API 强制直连，但应该只对 DashScope 生效
2. **超时时间过短**：60秒超时对 MiniMax API 可能不够
3. **缺少 MiniMax 专用 fallback**：MiniMax 官方 API 不稳定时没有备选方案

## 修复内容

### 1. 修复代理配置逻辑
- `getDirectFetchOptions(baseUrl)`：只对 `dashscope` 域名强制直连
- 其他 API（如 MiniMax）正常走系统代理配置

### 2. 调整超时和重试
- 超时时间：60s → 120s
- 增强错误日志：记录 URL、错误类型、错误代码

### 3. 添加 MiniMax Fallback 机制
- MiniMax 官方 API 失败 → 自动切换到百炼版 `MiniMax-M2.5`
- 保持原有的 DeepSeek fallback 作为最后备选

### 4. 流式合并优化
- 恢复合适的批量参数：`max_chars: 15, idle_ms: 25`
- 修复思考标签：`</think>` 结束标记
- 调整打字机速度：fast(45ms), medium(80ms), slow(140ms)

## 影响文件

- `oct-gateway/ai.js`：代理配置、超时、fallback 逻辑
- `oct-gateway/config.json`：流式合并参数
- `src/utils/cotExtract.ts`：思考标签修复
- `src/contexts/SettingsContext.tsx`：打字机速度
- `src/hooks/useTypewriter.ts`：字符延迟优化

## 测试建议

1. 重启 Gateway：`node --watch index.js`
2. 测试 MiniMax 对话：观察流式效果和稳定性
3. 验证 fallback：在网络不佳时应自动切换到百炼版
4. 检查思考标签：确保 `<think>` 内容正确隐藏
