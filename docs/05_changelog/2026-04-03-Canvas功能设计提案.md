# OCT Canvas 功能设计提案

## 1. 背景与目标

参考 Claude Code 的 Canvas 功能，实现一个 AI 驱动的可视化协作面板：

- **AI 主动创建**：不等待用户请求，AI 可以自己创建结构图、流程图、UI 设计
- **实时可视化**：支持 Mermaid 图表、SVG、React 组件预览
- **主动弹出**：AI 判断"这个用图表更好"时，自动打开 Canvas Panel
- **双向通信**：用户编辑的内容能被 AI 感知，AI 继续优化

## 3. 分阶段实现

### Phase 1: Canvas Panel 基础框架

**目标**：创建一个可用的 Canvas Panel 窗口

**新增文件**：
- `electron/canvas-panel.html` — Canvas 窗口的 HTML 入口
- `src/ui/canvas/CanvasPanel.tsx` — React 组件
- `src/components/canvas/MermaidRenderer.tsx` — Mermaid 图表渲染
- `src/components/canvas/SvgRenderer.tsx` — SVG 渲染
- `src/components/canvas/ComponentPreview.tsx` — React 组件预览

**CanvasPanel 功能**：
- 左侧：文件树（Canvas 创建的各种内容）
- 中间：渲染区域（Mermaid / SVG / 组件）
- 右侧：AI 对话气泡（解释当前内容）
- 底部：编辑工具栏

**Electron 配置**：
- `electron/main.ts` 新增 `createCanvasWindow()` 方法
- 支持通过 IPC 从 ChatTab 控制 Canvas 窗口的显示/隐藏

---

### Phase 2: AI → Canvas 通信协议

**目标**：让 AI Gateway 能够主动推送 Canvas 更新

**WebSocket 协议扩展**：

新增 `canvas` 类型的 `assistant` 消息：

```typescript
interface CanvasMessage {
  type: 'canvas';
  action: 'create' | 'update' | 'delete' | 'explain';
  payload: {
    id: string;           // 唯一标识
    title?: string;      // 文件标题
    contentType: 'mermaid' | 'svg' | 'component' | 'markdown';
    content: string;      // Mermaid 代码 / SVG / React 组件
    explanation?: string; // AI 对这段内容的解释
    parentId?: string;   // 父节点（用于组织文件树）
  };
}
```

**oct-gateway 改动**：
- 新增 `canvas_tool.js`：处理 Canvas 相关的 AI 工具调用
- `orchestrator.js`：判断 AI 响应是否需要触发 Canvas 更新
- 通过 WebSocket 推送 `canvas` 类型的消息到前端

**前端改动**：
- `useWebSocket.ts`：新增 `canvas` 消息的处理逻辑
- `CanvasPanel`：接收并渲染 AI 推送的内容

---

### Phase 3: AI 主动触发机制

**目标**：让 AI 能判断何时应该创建 Canvas 内容

**触发方式**：

1. **规则触发**（简单）：
   - 用户说"画个流程图"、"帮我设计架构"时触发
   - 关键词匹配：`流程图`, `架构图`, `时序图`, `UI 设计`

2. **AI 决策触发**（高级）：
   - AI 在生成响应前，先分析"这段内容是否适合可视化"
   - 决策 prompt 示例：
     ```
     如果你的响应包含以下内容，考虑创建 Canvas：
     - 多个实体及其关系（架构图、ER图）
     - 步骤流程（流程图、时序图）
     - UI 布局或设计
     - 数据结构或算法步骤
     ```

**Canvas Tool 定义**（供 AI 调用）：

```typescript
// oct-gateway/tools/canvas.js
const canvasTool = {
  name: 'create_canvas',
  description: '创建一个可视化 Canvas 内容',
  parameters: {
    type: 'object',
    properties: {
      contentType: {
        type: 'string',
        enum: ['mermaid', 'svg', 'component', 'markdown']
      },
      content: { type: 'string', description: '可视化内容' },
      title: { type: 'string', description: '标题' }
    },
    required: ['contentType', 'content']
  }
};
```

---

### Phase 4: 用户交互增强

**目标**：让用户能编辑 AI 创建的内容，AI 感知变化继续优化

**功能列表**：
- Mermaid 代码可直接编辑，实时预览
- 支持拖拽调整节点位置
- 用户编辑后，AI 自动解释修改或提出建议
- 支持导出为图片（PNG/SVG）

## 6. 技术选型

| 功能 | 方案 | 理由 |
|------|------|------|
| Mermaid 渲染 | `mermaid` npm 包 | 支持主流图表类型 |
| SVG 编辑 | `@uiw/react-codemirror` + SVG 编辑器 | 代码级编辑体验 |
| 窗口管理 | Electron BrowserWindow API | 已有 Electron 基础 |
| AI 通信 | 复用现有 WebSocket 协议 | 减少改动 |
| 状态管理 | React Context + useReducer | 轻量级 |

---

## 7. 风险与挑战

| 风险 | 描述 | 应对 |
|------|------|------|
| AI 误触发 | AI 可能过度创建 Canvas 内容 | 规则优先，AI 决策其次 |
| Mermaid 渲染兼容性 | Mermaid 代码可能有语法错误 | 错误边界降级为代码展示 |
| 性能 | 大量 Canvas 内容可能影响性能 | 懒加载 + 虚拟化列表 |
| 窗口同步 | Canvas 和 ChatTab 状态可能不一致 | 共享 Store + IPC 同步 |
