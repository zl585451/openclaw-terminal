## 二、MiniMax 流式输出优化

### 问题定位

MiniMax 的“盖章感 / 顿感 / 系统被拖住”的主因，不是模型本身，而是：

- 前端流式阶段过度重渲染
- chunk 到来时 UI 刷新过于频繁
- 流式阶段还在做重型 markdown / block 解析

### 已做优化

- 对 `MiniMax-*` 模型，前端不再走传统打字机链路
- `useMessages` 改成按帧合并刷新 UI，而不是每个 chunk 直接推一次 React
- `MessageList` 流式阶段对 MiniMax 走轻量正文显示
- 流式阶段跳过部分重型 markdown / block / option 解析

### 追加（同分支第二轮收稳）

- **无思维链标记**的 MiniMax 流式：正文不再依赖每帧 `setState` 驱动 React 文本节点，改为在 `useMessages` 的 RAF 内对 `<pre>` 写 `textContent`，并调用 `scroll.reconcile()` 补偿锚点；整棵 `ChatTab` 在纯正文流式阶段基本不再每帧重渲染。
- **含 `[cot]` / `<redacted_thinking>` 等标记**时：正文仍每帧写 DOM，React 侧对 `MessageList` 刷新 **节流（约 50ms）**，用于 CoT 头部等仍需 React 的子树；`StreamState.COMPLETED` 时再强制刷一帧，减少尾部思维链落后。
- `MessageList` 对「无 CoT 标记」的 assistant 文本 **跳过** `extractAssistantCotAndMain` 全量扫描，降低节流帧上的 CPU。

### 再追加（整页被拖感 / 侧栏卡顿）

- **MiniMax 流式期间暂停网关日志写入 React state**（`useGateway(suspendRef)`）：日志仍入队，结束流式后 `flushPendingLogLines()` 一次性合并，避免 `openclaw-log-lines` 每条 RAF 触发整棵 `ChatTab` 重渲染（此前即使用 `frozenLogLines` 展示，父组件仍会随 `logLines` 刷新）。
- **流式时 `scroll.reconcile()` 节流至约 40ms**，减轻与滚动锚点相关的 layout 压力。
- **右侧栏拆为 `ChatTabRightPanel`**：`sidebarCollapsed` 与 `startTransition` 放在子组件内，折叠/展开不再带动主列 `MessageList` 重渲染。

### IPC 闭包与列表 props（减少历史消息无效重渲染）

- **`useWebSocket`**：`optionsRef.current` 每渲染同步；IPC `handleIncomingMessage` 内始终调用**最新** `onChatDelta` / `onUsage` 等，修复 `useEffect([], [])` 陈旧闭包（正确性 + 与流式优化一致）。
- **`useMessages` `onUsage`**：入队后 `requestAnimationFrame` 合并同一帧内多条 usage，再批量 `setState`。
- **`ChatTab.v2`**：`getToolDisplayName`、`onMessageContextMenu`（依赖 `ctxMenu.onContextMenu`）、`onQuoteQuestion` 使用 `useCallback`，避免打字机/流式 tick 时穿透 `ChatMessageItem` memo。

### MiniMax「刷油漆」式平滑出字

- 网关仍可能一次推一大段字；此前整段写入 `<pre>` 会像「大块蹦字」。
- 现改为：缓冲区立刻收满 `fullTextRef`，**展示长度**用 RAF 链按帧向目标追赶（步长随积压与 **设置里的流式速度 / `streamSpeedMs`** 变化），视觉上更接近连续刷过去；仍走 DOM，不增加 React 逐字渲染。
- 新轮对话在 `sendMessage` / `quickSend` 时重置展示进度并取消未完成的 paint RAF。

### 触觉再调（减轻「生硬 / 拖感」）

- **步长**：由 `ceil(behind / 2.2)` 改为按落后比例 `round(behind * 0.32)` 并设上限（约 `165 / streamSpeedMs`，封顶 18），大段到达时更少「整坨蹦字」。
- **`scroll.reconcile`**：间隔由约 40ms 调至约 **56ms**，减轻与 `textContent` 触发布局在同一节奏内叠测几何的卡顿感。
- **含 CoT 标记时 React 节流**：由约 50ms 调至约 **72ms**，略减头部子树刷新频率。

### 当前效果

- “像系统负载过重那样被拖住”的顿感已明显下降
- 仍然不是完美逐字，但已经从“盖章式输出”改进为更顺的原生流式感
