# 2026-05-10 结构化 Markdown 流式渲染

## 背景

聊天区原先在 AI 流式输出阶段使用纯文本 `<pre>` 承接内容，等流结束后再切换为完整 Markdown 渲染。这能减少重排，但代码块、表格等结构只能在结束后一次性出现，不符合“容器先出现，文字流入容器”的阅读预期。

## 变更

- 新增 `StreamingMarkdownContent`，在流式阶段增量识别 Markdown 块：
  - 未闭合代码围栏会立即创建代码框，后续 token 在代码框内继续增长。
  - 表格在识别到表头和分隔行后立即创建 `<table>` 骨架，后续行进入对应单元格。
  - 同步支持标题、引用、列表和普通段落的轻量流式结构渲染。
- `useStreamPainting` 新增可见文本发布回调，在保持打字节奏的同时把当前可见内容交给 React 渲染结构。
- `ChatMessageList` 在流式 assistant 消息中切换到结构化 Markdown 渲染，最终完成后仍回到既有完整 Markdown 渲染路径。

## 效果

- 代码块不再等回复结束才出现，而是遇到 ``` 之后立即显示代码容器。
- 表格不再以纯文本整段滚动，而是先显示表格结构，再逐步填充单元格内容。
- 保留原有流式节奏、滚动跟随和结束后最终 Markdown 预处理能力。

## 体验优化

- 表格从第一行疑似表格内容开始就进入稳定表格外壳，避免先按段落渲染、分隔线到达后再突然切换成 `<table>`。
- 流式代码块改用与最终代码块更接近的深色代码容器和 Prism 高亮，减少流式期间与完成后之间的视觉跳变。
- 短表格保持内容宽度优先，不再默认铺满整条消息气泡；长内容仍可在容器内自然换行或横向滚动。
