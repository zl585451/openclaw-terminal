# 2026-04-03 流式打字机丝滑优化

## 问题
打字机输出"一坨一坨"，不流畅。用户设置"从容/细读"速度无效。

## 根因
1. **Gateway 层**：`createStreamMergeDelta` 按字符数分块，无语义感知
2. **前端层**：`baseDelayMs` 被简化版忽略，前端直接覆盖式 `setText`
3. **两层节奏不匹配**：Gateway 10ms/词，前端 debounce 40ms，每帧积攒 4-5 个词一起显示

## 解决方案

### 1. Gateway 新增 `createStreamSmoother` (`oct-gateway/index.js`)
用 `Intl.Segmenter` 按语义词边界分词，参考 Vercel AI SDK：
- 中文"你好"作为 1 个词一起发送
- 英文 "world" 作为 1 个词一起发送
- 标点独立发送

```javascript
const segmenter = new Intl.Segmenter('zh', { granularity: 'word' });
const INTERVAL_MS = 10;        // 10ms/词节奏
const CATCHUP_THRESHOLD = 30;  // 积压30字符开始追赶
const CATCHUP_CHARS = 5;       // 追赶时每tick按字符快速消费
```

### 2. WebSocket 消息处理改用 smoother (`oct-gateway/index.js`)
```javascript
const smoother = createStreamSmoother((chunk) => { ... });
await streamChat({ onDelta: smoother.feed, ... });
```

### 3. 恢复原版 RAF 逐字动画 (`src/hooks/useTypewriter.ts`)
关键参数：
- `MAX_CHARS_PER_FRAME = 6` — 每帧最多 6 字符
- `BATCH_FRAMES = 1` — 每帧都更新 React state（~16ms）
- `budgetRef` 初始值 = 30ms — 第一帧更有内容
- 追赶触发：elapsed > 1000ms, backlog > 40 字符
- `baseDelayMs`（从容=28ms / 细读=45ms）生效，控制打字速度

## 修改文件
- `oct-gateway/index.js` — 新增 createStreamSmoother，WebSocket 改用 smoother
- `src/hooks/useTypewriter.ts` — 恢复 RAF 逐字动画

## 效果
- 中文"你好 world"：原来逐字"你→好→ →w→o→..."，现在按词"你好→world→，"
- 用户"从容/细读"设置生效，打字速度可调节
- 追赶机制确保 AI 输出快时不卡顿
