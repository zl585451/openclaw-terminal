# 2026-04-10 发布前配置与代理策略收口

## 目的

为打包发布做最后一层默认安全配置，避免把开发期习惯直接带入产品版。

## 本次调整

### 1. 仓库默认配置不再携带真实 API Key

- `oct-gateway/config.json`
  - `minimax.api_key` 改为空字符串

说明：
- 发布包与仓库默认值不得包含真实密钥
- 用户应在设置页、`.env` 或用户目录配置文件中自行填写

### 2. 代理策略从“强制直连”改为“仅本地服务绕过代理”

- `electron/main.ts`
- `oct-gateway/config.js`
- `oct-gateway/mcp/client.js`

调整后策略：
- 保留用户系统代理，用于访问外部模型 API
- 自动把 `localhost` / `127.0.0.1` / `::1` 写入 `NO_PROXY`
- 避免本地 Gateway、MCP、本地能力服务被代理错误接管

这样更适合：
- 普通用户网络环境
- 公司代理环境
- 产品级发布场景

### 3. README 同步说明产品默认行为

- `oct-gateway/README.md`

新增说明：
- OCT 默认只为本地服务设置 `NO_PROXY`
- 不再强制所有外部 API 直连

## 发布意义

这次收口后，发布版默认行为更接近产品级预期：

- 不泄露密钥
- 不强行破坏用户代理环境
- 本地服务仍能稳定直连

## 仍需继续关注

- 首次启动配置引导是否足够产品化
- 本地服务（如 Nocturne / AI Library）失败时的用户提示是否足够清楚
- 未提交的本地开发规则文件（如 `CLAUDE.md`）不得混入发布版本
