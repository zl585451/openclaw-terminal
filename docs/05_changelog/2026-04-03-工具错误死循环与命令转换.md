# 2026-04-03 工具错误死循环修复 + Windows 命令自动转换

## 问题 1：工具调用错误导致 Fallback 死循环

### 现象
复杂任务（多轮工具调用）时，网关崩溃退出，日志出现大量重复的 `MiniMax API failed, fallback to Bailian MiniMax` 直到进程崩溃。

### 根因
1. MiniMax 返回工具调用，gateway 执行完后把结果发回继续对话，但 MiniMax 返回 `HTTP 400: tool result's tool id not found`
2. catch 块触发 fallback 到 Bailian，Bailian 也失败（因为 tool 结果已经包含无效的 tool_call_id）
3. `canFallbackToBailian` 标志没有清除，导致无限 fallback 循环

### 修复
- `ai.js`：在 catch 块加 `isToolError` 检测，400/401/403 相关工具错误直接报错，不再 fallback
- `ai.js`：修复 `stopHeartbeat is not defined`（心跳变量作用域问题，已提升到 try 外）
- `ai.js`：修复 `baseUrl is not defined`（`fetchWithRetry` 函数内引用了外部 baseUrl）

## 问题 2：exec_command 在 Windows 上误用 Linux 命令

### 现象
AI 执行 `ls`、`find . -name "*.py" | head -30` 等命令报错 `'ls' 不是内部或外部命令` 等。

### 修复
- 新增 `oct-gateway/tools/command_converter.js`：Linux/Mac 命令自动转换为 Windows PowerShell/CMD
- 覆盖：`ls -la`、`find . -name`、`cat`、`head -n`、`tail -n`、`mkdir -p`、`rm -rf`、`cp -r`、`mv`、`touch`、`pwd`、`grep`（管道）、`sort`（管道）、`uniq`（管道）、`head`/`tail`（管道）、`2>/dev/null` 重定向等
- `exec_command.js` 现在先调用转换器再做执行，出错时也改进了错误输出（stderr + stdout）
