# 2026-04-10 MiniMax M2.7 配置对齐官网

## 背景

MiniMax Token Plan 最新文档已经把 `MiniMax-M2.7` 作为主力文本模型，并明确：

- 大陆区仍使用 `https://api.minimaxi.com/v1`
- `M2.7 / M2.7-highspeed` 需要 Token Plan 专属 API Key
- Token Plan API Key 与普通按量计费 API Key 不可互换

## 本次调整

### 1. Gateway 现在会优先加载 `.env.local`

- `oct-gateway/config.js`

这样和当前项目文档保持一致，也更符合本地开发习惯。

### 2. 默认模型切换到 `MiniMax-M2.7`

- `oct-gateway/config.json`
- `oct-gateway/config.example.json`

避免新接入时继续落到旧默认值。

### 3. 设置页与测试连接补充 MiniMax 提示

- `src/ui/settings/tabs/ConnectionTabView.tsx`
- `electron/main.ts`
- `oct-gateway/providers.js`

补充内容：

- 设置页明确提示 MiniMax 需要 Token Plan API Key，通常以 `sk-cp-` 开头
- 测试连接时对明显错误的 Key 类型给出更直接的报错
- 获取 API Key 链接改为 MiniMax Token Plan 官方入口

### 4. 移除对 MiniMax 文本模型的视觉能力误判

- `oct-gateway/providers.js`
- `oct-gateway/config.js`
- `oct-gateway/services/imageService.js`

根据官方当前文档，MiniMax 的文本 OpenAI 兼容接口暂不支持图像/音频输入，因此不再把 `MiniMax-M2.*` 视为原生 inline vision 模型。

## 结果

- 新的 MiniMax 接入方式和官网口径保持一致
- `.env.local` 中的 MiniMax 配置会真正生效
- `M2.7` 鉴权问题更容易被定位出来
- 发图时不再错误走到 MiniMax 不兼容的 inline vision 请求体
