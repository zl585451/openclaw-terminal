# 2026-04-19 生图 provider 强隔离与显式回退开关

## 变更背景

生图链路曾出现“当前生图服务商与实际使用 key 不一致”导致的鉴权失败。根因是旧逻辑在 `IMAGE_API_KEY` 为空时，会隐式回退聊天 Key，容易跨服务商串 key。

## 本次改动

1. 设置页新增生图 provider 私有字段
- `IMAGE_MINIMAX_API_KEY / BASE_URL / MODEL`
- `IMAGE_SILICONFLOW_API_KEY / BASE_URL / MODEL`
- `IMAGE_OPENAI_API_KEY / BASE_URL / MODEL`

2. 新增回退开关
- `IMAGE_ALLOW_FALLBACK_TO_CHAT_KEY`，默认 `false`
- 默认严格隔离：仅使用生图 provider 对应独立 key（及兼容字段）
- 仅在开关为 `true` 时允许回退聊天 key

3. 前端 UI 联动更新
- 切换“生图服务商”时，自动加载该服务商对应的生图 Key/BaseURL/Model
- 编辑“生图 Key/BaseURL/Model”时，仅写入当前生图服务商的私有字段（同时镜像到兼容字段）
- 文案改为“默认不复用聊天 Key”

4. Gateway 生图路由更新
- `oct-gateway/index.js` 向 `image_gen` 传递全部生图私有字段与回退开关
- `oct-gateway/image_gen.js` 运行时按 provider 解析配置，优先私有字段，再兼容字段，最后按开关决定是否回退聊天 key

5. 能力判定修正
- `useCapabilities` 生图可用性判定改为“provider 私有 key 优先 + 可选回退”，避免“欢迎卡可用但实际生图失败”的假阳性

## 兼容性

- 旧字段 `IMAGE_API_KEY / IMAGE_BASE_URL / IMAGE_MODEL` 仍保留并继续生效（兼容旧配置）
- 新配置优先级高于旧字段
