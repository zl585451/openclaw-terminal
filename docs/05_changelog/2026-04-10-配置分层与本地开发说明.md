# 2026-04-10 配置分层与本地开发说明

## 目的

解决一个核心问题：

- **发布出去的版本要像产品**
- **本地开发环境不要被产品默认配置绑死**

## 本次补充

### 1. 新增安全示例配置

- `oct-gateway/config.example.json`

用途：
- 给开发者和发布流程一个“可公开的默认配置模板”
- 明确 API Key 不应硬编码在仓库默认配置中

### 2. 文档明确三层配置分工

更新：
- `oct-gateway/README.md`
- `docs/02_architecture/config-system.md`
- `docs/04_dev_guides/OCT 快速上手指南.md`

统一后的分层：

1. **仓库默认配置**
   - `oct-gateway/config.json`
   - 可提交、可打包
   - 不带真实密钥

2. **本地开发配置**
   - `.env.local` / `.env`
   - 只给开发者自己使用
   - 不提交

3. **用户运行时配置**
   - Electron `userData/config.json`
   - 由设置页写入
   - 属于安装后的本机数据

## 结果

这样处理后：

- 发布包默认更安全
- API Key 不再依赖仓库硬编码
- 开发者仍可通过 `.env.local` 保持自己的调试体验
- 产品默认值和本地开发覆盖项边界更清楚
