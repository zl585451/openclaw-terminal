# 打字机流畅度优化 v2 - 实现 Claude 般自然流畅感

## 问题描述
用户反馈打字机效果"一愣一愣"，即使速度调快也不够流畅，无法达到 Claude 那种自然的逐字输出效果。

## 根本原因分析

通过全链路分析发现问题所在：

### 1. 网关层批处理延迟 (`oct-gateway/index.js:138`)
```javascript
idleTimer = setTimeout(flush, idleMs); // 25ms 合并
```
网关将 25ms 内的所有 token 合并成一批发送，导致前端收到的是"块状"数据而非流式数据。

### 2. 前端每帧字符数过多 (`useTypewriter.ts:202`)
每帧最多处理 8 个字符，造成"跳跃式"显示，缺乏逐字打字的细腻感。

### 3. 延迟参数不协调
- 基础延迟过低（5ms）
- 标点停顿倍数过小
- 整体节奏 unnatural

## 优化措施

### 1. 网关层优化 (`oct-gateway/config.json`)
```json
"stream_merge": {
  "min_chars": 1,
  "max_chars": 8,
  "idle_ms": 5    // 25ms → 5ms，接近实时流式
}
```

### 2. 前端打字机核心优化 (`useTypewriter.ts`)

#### 字符延迟函数
```typescript
function charDelayMs(ch: string, base: number): number {
  const d = Math.max(base, 15); // 保持自然阅读节奏的最小延迟
  if (ch === '\n') return d + d * 0.3;      // 轻微换行停顿
  if ('。！？…'.includes(ch)) return d + d * 0.2;  // 轻微句号停顿
  if ('.!?'.includes(ch)) return d + d * 0.15;     // 轻微英文句号停顿
  if (',，、;；'.includes(ch)) return d + d * 0.1; // 轻微逗号停顿
  return d;
}
```

#### 每帧字符数限制
```typescript
// 修改前
while (typedThisFrame < 8 && idx < fullLen)

// 修改后
while (typedThisFrame < 2 && idx < fullLen)
```
每帧最多显示 2 个字符，实现真正的逐字打字效果。

### 3. 速度档位重新设计 (`SettingsContext.tsx`)
```typescript
const SPEED_MS: Record<StreamSpeed, number> = {
  fast: 30,    // 快速流畅：约33字/秒，接近 Claude 的流畅度
  medium: 50,  // 自然舒适：约20字/秒，适合正常阅读
  slow: 90,    // 慢速细读：约11字/秒，逐字品味
};
```

## 流畅感原理

Claude 的流畅感来自于：
1. **高频小批量推送** - 每 5ms 推送 1-2 个字符
2. **逐字显示** - 每帧只渲染 1-2 个字符，而非批量
3. **自然延迟** - 基础 30-50ms 延迟符合人类视觉暂留（约 40ms）
4. **轻微标点停顿** - 让阅读有呼吸感，但不停顿太久
