# Agent 权限硬开关落地

> Date: 2026-04-19  
> Type: feature

## 变更内容

将设置面板“高级 → Agent 权限”从前端软拦截升级为后端硬权限控制：

- 任何工具执行前，都在网关 `tool_loader` 统一做权限校验。
- 权限开关配置写入 `userData/config.json` 的 `AGENT_PERMISSIONS`，并被网关运行时读取。
- `exec_command` 支持按命令内容二次判定（安装/系统配置/网络/文件写入）。
- 新增“未知 MCP 工具默认拒绝”策略：当存在关闭的权限开关时，无法识别风险能力的 MCP 工具被拒绝，避免通过改名/伪装工具绕过权限。
- 新增配置项 `AGENT_PERMISSIONS_STRICT_UNKNOWN_MCP_DENY`（默认 `true`），控制上述未知 MCP 工具拒绝策略。

## 修改文件

| 文件 | 变更 |
|---|---|
| `oct-gateway/tool_loader.js` | 新增 `enforceAgentPermission` 与运行时权限读取逻辑，执行工具前强制校验 |
| `oct-gateway/config.js` | 新增 `AGENT_PERMISSIONS` 默认值/归一化方法与运行时 setter |
| `electron/main.ts` | 新增 IPC：`get-agent-permissions`、`save-agent-permissions` |
| `electron/preload.ts` | 暴露 `getAgentPermissions`、`saveAgentPermissions` 给渲染进程 |
| `src/components/SettingsPanel.tsx` | “应用”时保存 Agent 权限到主进程配置 |
| `src/contexts/PermissionsContext.tsx` | 启动时从主进程读取真实权限状态 |
| `src/vite-env.d.ts` | 补充新增 IPC 的类型声明 |
| `oct-gateway/config.json` | 增加 `AGENT_PERMISSIONS` 示例字段 |

## 影响说明

- 权限开关不再是仅前端提醒；即使绕过前端，后端仍会拒绝未授权的工具调用。
- MCP 工具同样受控，包含文件操作类外部工具。

## 后续修复（同日）

- 修复“高级设置点击应用后权限未落盘”的问题：
  - 根因：`electron/preload.ts` 未暴露 `get-agent-permissions` / `save-agent-permissions`，前端调用被可选链静默跳过。
