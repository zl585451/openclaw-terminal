# 文档维护规范

> 版本：1.0.0 | 最后更新：2026-04-01

---

## 为什么必须维护文档

本项目采用**单人 + 多 AI 协作**模式：
- **你**提出需求
- **Claude/GPT** 提供方案咨询
- **Cursor Agent** 执行代码

**文档是 AI 之间传递上下文的核心媒介。** 不维护文档会导致：
- AI 对架构理解偏差
- 重复实现已废弃的功能
- 代码与文档脱节
- 协作效率下降

---

## 工程师 AI 工作规则

以后工程师型 AI（包括小模型）修改代码时，必须遵循：

1. 先进入 `docs/00_ai_entry/README.md`
2. 根据问题类型阅读对应入口文档
3. 沿入口文档列出的核心文件排查与修改
4. 修改完成后同步更新入口文档与 changelog

禁止做法：

- 不看入口文档就直接全仓搜索后改代码
- 把历史重构文档当成当前实现事实
- 改了链路却不回填文档

## 提交时必须更新的文档

### 1. Changelog（强制）

**每次提交都必须创建或更新。**

**文件命名**：`docs/05_changelog/YYYY-MM-DD-简述.md`

**模板**：
```markdown
# YYYY-MM-DD 变更记录

## 变更类型
- [ ] 新功能
- [ ] Bug 修复
- [ ] 性能优化
- [ ] 重构
- [ ] 文档更新
- [ ] 其他

## 变更内容
### 新增
- 功能 A：简述

### 修改
- 功能 B：从 X 改为 Y

### 删除
- 功能 C：原因

## 影响范围
- 前端：...
- 后端：...
- 协议：...

## 测试情况
- [ ] 单元测试通过
- [ ] 手动测试通过
- [ ] 未测试（说明原因）

## 关联文档
- 架构更新：docs/02_architecture/xxx.md
- 协议更新：docs/03_specs/xxx.md
```

---

### 2. 架构文档（修改架构时）

**何时更新**：
- 新增/删除模块
- 修改数据流向
- 变更技术栈
- 调整目录结构

**更新位置**：`docs/02_architecture/`

---

### 3. 技术规范（修改接口/协议时）

**何时更新**：
- WebSocket 消息格式变更
- 渲染协议调整
- API 接口变化
- 配置文件格式变更

**更新位置**：`docs/03_specs/`

---

### 4. 开发指南（修改使用方式时）

**何时更新**：
- 新增命令/快捷键
- 修改配置方式
- 新增开发流程
- 变更部署步骤

**更新位置**：`docs/04_dev_guides/`

---

### 5. 系统提示词（修改 AI 行为时）

**何时更新**：

- 工具使用规范修改
- 新增/删除系统命令

**更新位置**：`docs/01_system_prompts/`

## 文档更新流程

```
1. 修改代码
   ↓
2. 同步更新对应文档
   - 创建 changelog
   - 更新架构/规范/指南（如需要）
   ↓
3. 提交时包含文档变更
   git add docs/05_changelog/YYYY-MM-DD-xxx.md
   git add src/xxx/xxx.ts
   git commit -m "类型：简述"
   ↓
4. 代码审查时检查文档同步性
```

---

## 文档质量标准

### 必须做到
- ✅ 每次提交都有 changelog
- ✅ 架构文档与代码一致
- ✅ 接口变更同步更新协议文档
- ✅ 废弃功能在文档中标记

### 禁止
- ❌ 代码改了文档没改
- ❌ 文档描述与代码行为不符
- ❌ 复制粘贴旧文档不更新
- ❌ 只有代码提交没有文档更新

---

## 退回标记

若需临时跳过文档更新（仅限紧急修复），在提交信息中注明：
```
git commit -m "修复：紧急修复 XXX（文档待补充）"
```

并在 `docs/05_changelog/` 创建占位文件：
```markdown
# YYYY-MM-DD 紧急修复

**状态**：文档待补充
**原因**：紧急修复，文档将在 X 小时内补充
```
