# 内容制作多 Agent 系统架构

## 文档状态

- 版本：v1.0
- 状态：架构基线草案，可作为后续内容制作 Agent 系统的总设计参考
- 生效方式：先用于统一概念、职责边界和扩展方向，后续随真实流水线实现迭代
- 修订原则：先平台化，再模板化；先稳定数据契约，再扩展 Agent 数量

---

## 1. 文档目的

本文档用于将当前“多人演播有声小说改编”规则上抽为一个更通用的内容制作多 Agent 系统。

核心判断是：

**有声小说不是一个孤立模块，而是内容制作多 Agent 平台上的一个团队模板。**

未来同一套平台可以承载：

1. 有声小说制作团队
2. 广播剧制作团队
3. 短剧改编团队
4. 漫画分镜团队
5. 影视剧本开发团队
6. 其他可组合的内容生产工作流

---

## 2. 核心设计原则

### 2.1 平台和团队分离

系统不应把“有声书”写死为唯一形态。

建议分成两层：

1. **平台层**
   负责 Agent 注册、任务编排、上下文管理、产物存储、质检闭环和人工介入。
2. **团队模板层**
   负责定义某一类内容任务需要哪些 Agent、执行顺序、输入输出和验收规则。

### 2.2 Agent 不直接等于流程

Agent 是可复用能力单元，流程是对 Agent 的编排。

同一个 Agent 可以出现在不同团队中，例如：

1. 角色关系分析 Agent 可用于有声小说、广播剧、短剧。
2. 连贯性质检 Agent 可用于小说改编、剧本改编、分镜脚本。
3. 风格统一 Agent 可用于所有长文本项目。

### 2.3 产物优先，而不是聊天优先

多 Agent 系统的核心不应只是“谁回复了什么”，而应该是每一步生成了什么稳定产物。

建议所有 Agent 都围绕产物工作：

1. 原文结构
2. 剧情锁定表
3. 角色表
4. 场景表
5. 改编稿
6. 角色音标注
7. 演播设计
8. 质检报告
9. 导出脚本

### 2.4 保留不确定性

内容制作中很多判断不能一次确定，例如未知说话人、伏笔、后文角色回绑、统筹分配。

因此系统应允许：

1. `待确认`
2. `独立占位`
3. `可回绑`
4. `低置信度候选`
5. `需人工确认`

这些状态必须是一等数据，而不是备注里的模糊说明。

---

## 3. 总体架构

建议采用以下结构：

```text
用户需求 / 项目目标
        ↓
制作总控 Orchestrator
        ↓
项目上下文层 Project Context
        ↓
团队模板 Team Template
        ↓
Agent 编排 Pipeline
        ↓
结构化产物 Artifact Store
        ↓
质检 / 回滚 / 人工确认
        ↓
导出与交付
```

---

## 4. 平台层能力

平台层不关心具体是有声小说还是广播剧，它只提供通用能力。

### 4.1 Agent 注册表

每个 Agent 应声明：

1. 名称
2. 职责
3. 输入产物
4. 输出产物
5. 可用工具
6. 是否允许改正文
7. 是否允许产生新角色
8. 是否需要人工确认
9. 适用团队模板

### 4.2 团队模板注册表

每个团队模板应声明：

1. 模板名称
2. 适用任务
3. 默认 Agent 列表
4. 默认执行顺序
5. 可选 Agent
6. 必要产物
7. 质检标准
8. 导出格式

### 4.3 产物存储

建议将每一步结果作为结构化产物保存，而不是只保存最终文本。

推荐产物类型：

1. `source_text`
2. `chapter_outline`
3. `plot_lock`
4. `scene_map`
5. `character_registry`
6. `voice_registry`
7. `adapted_script`
8. `performance_design`
9. `review_report`
10. `export_package`

### 4.4 任务编排

编排不应只支持线性流程，也应支持分支和返工。

建议支持：

1. 顺序执行
2. 并行分析
3. 条件分支
4. 人工确认节点
5. 质检打回
6. 局部重跑

---

## 5. 团队模板层

团队模板是把一组 Agent 组织成具体生产线的方式。

### 5.1 有声小说团队模板

当前已定义的规则可归入这个团队模板。

默认链路：

1. 文本口语化改编 Agent
2. 角色音分类标注 Agent
3. 演播设计 Agent
4. 质检 Agent

已有规则文档：

1. `docs/03_specs/内容创作工作台/多人演播有声小说改编规则.md`
2. `docs/03_specs/内容创作工作台/多人演播角色音分类标注规则.md`
3. `docs/03_specs/内容创作工作台/多人演播演播设计规则.md`
4. `docs/03_specs/内容创作工作台/多人演播质检规则.md`

### 5.2 广播剧团队模板

广播剧不是有声小说的简单加强版，建议单独建团队模板。

可能包含：

1. 剧情场景化 Agent
2. 对白戏剧化 Agent
3. 角色冲突增强 Agent
4. 声音舞台设计 Agent
5. 分集节奏 Agent
6. 广播剧质检 Agent

广播剧模板允许更强的改编，但必须在项目级规则中明确授权。

### 5.3 通用内容分析团队模板

适用于非交付型任务，例如分析小说、整理世界观、建立角色库。

可能包含：

1. 章节解析 Agent
2. 角色关系 Agent
3. 时间线 Agent
4. 伏笔追踪 Agent
5. 世界观整理 Agent
6. 连贯性审查 Agent

### 5.4 导出与格式化团队模板

适用于把已有产物转换成不同交付格式。

可能包含：

1. YAML 导出 Agent
2. Markdown 脚本导出 Agent
3. 剧组统筹表导出 Agent
4. CV 角色表导出 Agent
5. 审校报告导出 Agent

## 6. 通用 Agent 池

以下 Agent 应设计为通用能力，而不是绑定某一个团队。

### 6.1 原文解析 Agent

负责章节切分、段落识别、对白识别、叙事层级识别。

### 6.2 剧情锁定 Agent

负责提取不可改信息，包括人物、时间、地点、线索、伏笔、因果。

### 6.3 场景切分 Agent

负责把章节拆成可制作的场景单元。

### 6.4 角色注册 Agent

负责建立角色库，包括姓名、身份、关系、首次出场、重要程度。

### 6.5 角色音分类标注 Agent

负责声音主体分类、占位、状态标注和后续回绑预留。

### 6.6 风格统一 Agent

负责检查同一项目中的语言风格、旁白风格、角色口吻是否稳定。

### 6.7 连贯性质检 Agent

负责检查剧情、人物、时间线、信息顺序和风格连续性。

### 6.8 导出 Agent

负责将结构化产物导出为剧组可用格式。

---

## 7. 项目上下文层

为了支持长项目和多团队协作，每个项目应有独立上下文。

建议包含：

1. 项目目标
2. 原文版本
3. 授权改编边界
4. 题材类型
5. 风格基线
6. 角色库
7. 术语库
8. 伏笔与保密点
9. 未决项列表
10. 人工确认记录

---

## 8. 运行粒度

系统应支持多种运行粒度，不能只绑定“一次做一章”。

### 8.1 单章模式

适合快速试跑、低成本生成和人工逐章审校。

特点：

1. 上下文少。
2. 判断保守。
3. 未知项较多。
4. 适合早期系统验证。

### 8.2 多章模式

适合角色回绑、伏笔追踪和长线连贯性检查。

特点：

1. 能建立跨章角色库。
2. 能合并未定声音。
3. 能更稳地识别伏笔。
4. 成本更高。

### 8.3 项目模式

适合整本书、整季广播剧或大型内容工程。

特点：

1. 需要项目级记忆。
2. 需要产物版本管理。
3. 需要人工确认节点。
4. 需要导出与审校闭环。

---

## 9. 数据契约优先级

系统后续能否扩展，关键不在于一开始有多少 Agent，而在于产物契约是否稳定。

建议优先定义以下 schema：

1. `ProjectContext`
2. `ChapterUnit`
3. `SceneUnit`
4. `CharacterRegistry`
5. `VoiceRegistry`
6. `AdaptedScript`
7. `PerformanceDesign`
8. `ReviewReport`
9. `ExportPackage`

每个 Agent 都应明确：

1. 读取哪些 schema。
2. 产出哪些 schema。
3. 是否会修改已有 schema。
4. 修改时是否保留版本。

---

## 10. 人工介入节点

内容制作系统必须允许人工介入，而不是追求全自动闭环。

建议设置人工确认节点：

1. 改编边界确认
2. 角色库确认
3. 未定声音回绑确认
4. 关键风格确认
5. 质检打回确认
6. 最终导出确认

---

## 11. 推荐演进路线

### 11.1 Phase 1：规则平台化

目标：

1. 将现有有声小说四份规则挂到“有声小说团队模板”下。
2. 定义 Agent 注册表和团队模板注册表。
3. 定义最小产物 schema。

### 11.2 Phase 2：有声小说团队跑通

目标：

1. 单章跑通完整链路。
2. 产出改编稿、角色音表、演播设计、质检报告。
3. 支持质检打回和局部重跑。

### 11.3 Phase 3：跨章能力

目标：

1. 建立项目级角色库。
2. 支持未定角色音回绑。
3. 支持伏笔和保密点追踪。

### 11.4 Phase 4：新增广播剧团队

目标：

1. 在同一平台层下新增广播剧团队模板。
2. 复用原文解析、角色注册、质检、导出等通用 Agent。
3. 新增戏剧化、场面化、冲突增强等专用 Agent。

### 11.5 Phase 5：多团队组合

目标：

1. 允许用户选择团队模板。
2. 允许多个团队共享同一项目上下文。
3. 允许同一原文生成多种交付物。

---

## 12. 当前结论

当前已有的有声小说规则不应废弃，也不需要推翻。

更合适的定位是：

**它们是内容制作多 Agent 系统中的第一套成熟团队模板。**

下一步不要急着增加大量新 Agent，而应先补齐三件事：

1. Agent 注册表
2. 团队模板注册表
3. 产物 schema

这三件事稳定后，有声小说、广播剧、短剧、漫画分镜都可以作为团队模板逐步接入。
