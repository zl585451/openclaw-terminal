## 1️⃣ 会话持久化缓存

**文件**：`oct-gateway/session.js`  
**机制**：写入 `~/.oct-gateway/sessions.json`，防抖 500ms，7 天过期清理

### 测试步骤

- [ ] 启动 OCT，发送 3-5 条消息
- [ ] 查看日志，确认出现 `[Session] 已加载 X 个历史会话`
- [ ] 检查文件 `~/.oct-gateway/sessions.json` 是否创建
- [ ] 查看文件内容，确认会话数据已写入
- [ ] **重启 OCT**
- [ ] 再次查看日志，确认加载了之前的会话（数量应增加）
- [ ] 发送新消息后，检查 sessions.json 是否更新
- [ ] （可选）修改系统时间到 8 天后，重启 OCT，确认过期会话被清理

### 预期结果

```
[Session] 已加载 3 个历史会话
[Session] 已加载 5 个历史会话（重启后）
```

## 2️⃣ 解析缓存（LRU Map）

**文件**：`src/utils/optionBoxParser.ts`  
**机制**：LRU Map，最多 200 条，key = 前 100 字符 + 长度

### 测试步骤

- [ ] 发送一条含选项框的消息（如"累吗？■ 累 ■ 不累"）
- [ ] 查看解析结果是否正常
- [ ] **发送完全相同的消息**
- [ ] 观察解析速度是否明显变快（或查看是否有缓存命中日志）
- [ ] 发送 201 条不同的选项框消息
- [ ] 确认最早的那条被挤出缓存（如有调试日志）

### 预期结果

- 第二次解析相同消息时，应该直接命中缓存
- 缓存超过 200 条时，最早的条目被清除

## 3️⃣ 抓取缓存（web_fetch）

**文件**：`oct-gateway/tools.js`  
**机制**：web_fetch 结果缓存 5 分钟 TTL，最多 100 条

### 测试步骤

- [ ] 用 `/fetch https://example.com` 抓取一个 URL
- [ ] 查看返回结果，确认 `cached: false`
- [ ] **立即再抓一次同一个 URL**
- [ ] 查看返回结果，确认 `cached: true`
- [ ] 等待 5 分钟
- [ ] 再次抓取同一个 URL
- [ ] 查看返回结果，确认 `cached: false`（已过期）
- [ ] （可选）连续抓取 101 个不同的 URL
- [ ] 确认最早的那个被挤出缓存

### 预期结果

```
第一次：{ success: true, content: "...", cached: false }
第二次：{ success: true, content: "...", cached: true }
5 分钟后：{ success: true, content: "...", cached: false }
```
