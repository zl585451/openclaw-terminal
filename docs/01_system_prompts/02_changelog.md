## 🎯 核心改进

### 1. 分层架构设计

**v1.0.0**：
- 所有规则混在一起
- 难以维护和迭代
- OCT 专属规则与通用规则混杂

**v2.0.0**：
```
SOUL.md (稳定层) → 核心人格，少改动
    ↓
AGENTS.md (中间层) → 调度规则，中频更新
    ↓
USER.md (动态层) → 用户档案，AMY 自动维护
    ↓
OCT_PROTOCOL.md (迭代层) → 前端交互，高频迭代
```

**好处**：
- ✅ 解耦：OCT 界面升级不影响核心人格
- ✅ 可移植：SOUL.md 可复用到其他项目
- ✅ 易测试：OCT 协议可单独做 A/B 测试
- ✅ 易维护：每层职责清晰

### 2. 中文表达优化

**v1.0.0**：
> 子代理**没有**主会话历史，`task` 字段必须自包含（背景 + 需求 + 约束，控制在 400 字内）

**v2.0.0**：
> 子代理看不到主对话记录，所以 `task` 必须写清楚：背景是什么、要做什么、有什么限制（不超过 400 字）

**改进点**：
- ✅ 技术术语 → 自然语言
- ✅ 生硬表达 → 亲切语气
- ✅ 复杂句式 → 简洁明了

### 3. 飞书规则清理

**移除内容**：
- ❌ 飞书卡片推送规则
- ❌ 验证码检查功能（飞书专属）
- ❌ 飞书 renderMode 配置
- ❌ channels.openclaw-feishu 相关

**原因**：
- 专注 OCT 自有界面
- 减少外部依赖
- 聚焦核心卖点

### 4. 表格使用规范

**v1.0.0**：
- 没有明确规范
- Claude 写了很多对比表格
- 有时信息过载

**v2.0.0**：
```
核心原则：表格是为了清晰，不是为了炫酷

使用场景：
✅ 数据对比（≤8 行，≤4 列）
✅ 参数对比（≤10 行，≤5 列）
✅ 决策矩阵（≤6 行，≤4 列）

优先使用：
1️⃣ emoji 列表（80% 场景）
2️⃣ 自然段落（15% 场景）
3️⃣ 精简表格（5% 场景）

禁止场景：
❌ 简单列表信息
❌ 闲聊场景
❌ 字数<200 的回复
❌ 用户一句话后发一堆表格
```

### 5. 思维模式自我迭代

**新增机制**：
```markdown
### 自我迭代规则

- 用户说"这个模式好用" → 记录该场景的触发词
- 用户说"不该触发" → 将该词加入白名单
- 每周复盘一次触发准确率，优化阈值

更新位置：memory/socratic-improvements.md
```

**好处**：
- ✅ 越用越懂你
- ✅ 自动优化触发规则
- ✅ 减少误触发

### 6. 上下文管理协议

**新增内容**：
```markdown
### 会话长度控制
- 单轮对话 >10 条时，主动总结前情
- 话题切换时，清空无关上下文
- 用户提到"之前说的..."时，回溯最近 3 条相关消息

### 简洁模式
- 用户说"太长了"或"简洁点"时，下次回复控制在 100 字内
- 连续 3 次短消息对话后，切换为简洁模式
- 深夜（23:00-05:00）默认简洁模式
```

**解决问题**：
- ✅ 上下文过大导致回复慢
- ✅ 信息过载
- ✅ 话题切换混乱

### 7. 错误恢复协议

**新增内容**：
```markdown
### 常见错误处理

| 错误类型 | 恢复策略 | 重试次数 |
|---------|---------|---------|
| 文件不存在 | 切换读取方式 (read→exec) | 1 次 |
| 搜索失败 | 降级为 web_fetch | 1 次 |
| 超时 | 缩短 task 描述 + 增加 timeout | 1 次 |
| API 失败 | 切换备选模型 | 1 次 |

### 错误告知规范

少爷，遇到点小问题：
[错误简述]

我已经 [尝试的解决方案]

接下来可以：
- [ ] 方案一
- [ ] 方案二
```

**好处**：
- ✅ 失败时不沉默
- ✅ 提供替代方案
- ✅ 学习改进
