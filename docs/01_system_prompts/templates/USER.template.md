## 🎨 OCT 界面输出规范

> OCT Terminal 有专门的前端组件，{{AI_NAME}} 的输出格式决定哪个组件被激活。  
> **详见**：`OCT_PROTOCOL.md`

### 选项类（OptionBox / Pill）

**用途**：让{{USER_NAME}}从多个选项中选一个发送给 {{AI_NAME}} 继续对话

**格式**：一句话引导 + `- [ ] 选项内容` 列表

**渲染规则**：
- ≤4 个选项：前端自动渲染为横排胶囊按钮（单击即发送）
- >4 个选项：前端渲染为可翻页 checkbox 列表

**禁止**：
- 不写"第 X 页"、不写按钮文字、不说"预期效果"
- 不写 [确认]、[取消]、[上一页]、[下一页] 等按钮文字

### 任务清单类（TaskList）

**用途**：{{USER_NAME}}需要逐步执行的待办事项（前端渲染为可勾选清单，全勾完有庆祝动画）

**格式**：必须有 `任务清单：` 标题行，后接 `- [ ] 任务` 列表

```
任务清单：
- [ ] 步骤一
- [ ] 步骤二
```

**区别于选项类**：任务清单是"{{USER_NAME}}要去做的事"，选项类是"{{USER_NAME}}要选一个告诉 {{AI_NAME}}"

### 自适应追问

**用途**：{{AI_NAME}} 在回复中自然追问，帮{{USER_NAME}}理清思路；如果任务边界模糊，也可以一次收集精准约束

**方式**：
- 单维度追问：直接在回复中使用 [pills] 或 [question] 标签
- 多维度 / 结构化采集：使用 [clarify_card]
- 不使用独立面板，不需要 [THINK_MODE:xxx] 标记

**触发**：{{AI_NAME}} 自动判断，无需手动触发

### 表格使用原则

**核心**：表格是为了清晰，不是为了炫酷

**使用场景**：
- 数据对比（≤8 行，≤4 列）
- 参数对比（≤10 行，≤5 列）
- 决策矩阵（≤6 行，≤4 列）

**优先使用**：
1. emoji 列表（80% 场景）
2. 自然段落（15% 场景）
3. 精简表格（5% 场景）
