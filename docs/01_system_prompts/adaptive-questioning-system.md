# OCT 自适应提问系统（Adaptive Questioning System）

> **核心理念**：把“思维模式面板”从独立组件降级为 AI 回复策略，让追问像呼吸一样自然。  
> **推荐命名**：Adaptive Clarification（自适应澄清）  
> **内部代号**：InlineSocratic（仅开发侧可用，对用户隐藏）

---

## 一、旧架构 vs 新架构（结论）

### 旧架构（已废弃）

用户消息 → 关键词匹配 → THINK_MODE 标记 → 弹出面板 → 固定模板提问 → 汇总后发送

问题：
- 固定模板覆盖不足
- “弹面板/切流程”体验机械、打断对话

### 新架构（目标形态）

用户消息 → AMY 自主判断（Prompt 层） → **回复中自然追问** + 嵌入交互标签 → 用户一键回复 → 继续对话

结论：
- **完全去掉“思维模式面板”概念**
- 前端不新增组件；追问交互完全复用现有 `[pills]` / `[question]` / `[checkbox]` / `[tasklist]`

---

## 二、系统设计（接入点）

### 2.1 Prompt 层（Gateway）

- 将 `CLARIFICATION_PROTOCOL.md` 注入 system prompt，作为 AMY 的追问规则源
- `OCT_PROTOCOL.md` 保留“渲染协议”与“交互约束”，不再描述旧面板机制

### 2.2 前端渲染层（React）

无需新增组件，只需解析/渲染成对标签：
- `[pills]...[/pills]` → OptionBox（胶囊）
- `[checkbox]...[/checkbox]` → OptionBox（多选）
- `[question]...[/question]` → QuestionCards
- `[tasklist]...[/tasklist]` → TaskList

## 三、输出策略（核心逻辑）

### 3.1 何时追问

当出现以下信号时，优先使用自适应澄清：
- 意图模糊、信息不足
- 选择困难、隐含冲突、多重目标
- 开放性问题（“接下来做什么”）

以下情况不追问或最小澄清：
- 明确指令（直接执行）
- 情绪宣泄（先共情）
- 简单事实问题（直接回答）

### 3.2 如何追问（约束）

- 先给价值/框架，再追问（不空手追问）
- 一次只问一个维度
- 最多追问 2 轮；第 3 轮必须给可执行建议
- 追问回复 < 200 字；选项 2-4 个，每个 < 15 字
- 一条消息只用一种交互标签（避免混用冲突）

---

## 四、迁移要点（工程侧）

### 4.1 需要删除/停止使用

- THINK_MODE 标记与相关 UI（按钮/菜单/面板）
- 固定模板触发逻辑（关键词映射、模板问答状态）

### 4.2 必须保留

- 成对标签渲染协议（OptionBoxParser 与对应组件）
- 历史消息兼容：如存在旧标记，显示前可做清理（不影响新对话）
