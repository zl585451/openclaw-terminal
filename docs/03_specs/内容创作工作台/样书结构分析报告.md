# 样书结构分析报告

- 日期：2026-05-01
- 样本目录：`D:\下载\样书`
- 目标：为“小说原文 → 多人演播台本”的 Agent 提示词、结构协议、质检规则提供样本依据。

## 1. 结论摘要

本轮样本不建议继续用“单 Agent 直接产出台本”或“分类 prompt 局部补丁”的方式推进。五本样书已经覆盖了多种高频小说结构：未知说话人开场、群体对白、系统音、第一人称叙述、后置说话人、旁白夹对白、西幻人名、编码与章节标题异常。

更合适的方向是建立一条可验证的结构流水线：

1. 导入层识别编码、章节标题和基础文本 span。
2. 程序抽取 quote span、旁白 span、说话提示 cue、系统音和冒号标签。
3. 归属 Agent 只判断 quote 的 speaker，不改写文本。
4. 程序基于 span 合成台本，避免对白在旁白中重复。
5. 角色表由角色实体注册表生成，不直接统计 speaker 字符串。
6. QC 对协议残留、占位 speaker、旁白含对白、重复对白做硬拦截。

## 3. 关键结构类型

### 3.1 未知说话人开场

代表样本：

- 《夫人请卸甲》第1章开头连续三句：“醒了？”、“感觉如何？舒服吗？”、“宁解元——”
- 《你们再吹》第2章开头连续群体议论
- 《谁让他莽上去的！》第1章开头：“今天看来是阳光明媚的一天。”

处理原则：

- 不允许硬猜成主角。
- 可生成占位声线：`未定女声A`、`外门弟子群A`、`主角自语`。
- speaker 必须带 `confidence` 与 `evidence`。
- 如果后文揭示身份，应支持同章回绑。

### 3.2 旁白夹对白

代表样本：

- `他都还没来得及思考怎么回事，那送饭的狱卒便放下木盘，“快些吃吧...”`
- `王大山开门见山道：“我现在是湘南府望族周家三夫人的外院管事...”`
- `“愣着干什么...”一边脱着碍事的衣服，伊莱一边对两位漂亮女侍卫说道。`

当前风险：

- 旁白保留整段原文，之后又拆出 dialogue，造成对白重复。
- 后置 cue 的 speaker 容易漏掉。

处理原则：

- quote span 从旁白 span 中扣除，旁白不再包含引号对白。
- cue 可来自 quote 前，也可来自 quote 后。
- 同一自然段允许生成多个 segment，但必须互不重叠。

### 3.3 群体对白与未命名角色

代表样本：

- 《你们再吹》第2章，外门弟子连续议论苏尘。
- 《八零之福运小寡妇》第2章，警察、村民、小军等同场。

处理原则：

- 群体发言不强行拆成具体角色。
- 可用 `外门弟子A`、`外门弟子群`、`警察A`、`村民A`。
- 如果后文出现明确姓名，再做实体合并。

### 3.4 系统音 / 非人物声音

代表样本：

- 《你们再吹》第1章：`【叮……】`、`【神级吹嘘系统，正在绑定。】`

处理原则：

- 单独类型：`system_voice` 或 `sfx_system`。
- 不进入普通角色音 main/support。
- 可进入功能声线：`系统音`。

### 3.5 第一人称叙述与自言自语

代表样本：

- 《我靠出马成名了》第1章：“我叫白梓瞳。”
- 主角自述、吐槽、回忆与真实对白混在一起。

处理原则：

- 第一人称旁白不是自动 `inner_monologue`。
- 有引号且明显说出口，才进入 dialogue。
- 无引号但为角色脑内原声，可标 `inner_monologue`；否则保留 narration。

### 3.6 后置说话人

代表样本：

- `“你真的会帮我照顾小军吗？”宋小花用力咬着唇，为难地说道。`
- `“愣着干什么...”一边脱着碍事的衣服，伊莱一边对两位漂亮女侍卫说道。`

处理原则：

- quote attribution 不能只看前文。
- 每个 quote 需要左右窗口：左侧 80-160 字、右侧 80-160 字。
- cue extraction 应输出 `preCue` / `postCue`。

### 3.7 非标准章节与编码问题

代表样本：

- 《八零之福运小寡妇》使用 `【001】逼婚致死的小姑娘`。
- 文件编码为 GB18030，按 UTF-8 会乱码。

处理原则：

- 导入层必须做编码检测或 fallback：UTF-8 → GB18030。
- 章节正则不能只支持 `第X章`，至少支持：
  - `第1章 标题`
  - `第001章 标题`
  - `【001】标题`
  - `001 标题`

## 4. 对 Agent 协议的要求

### 4.1 不让 Agent 直接产最终台本

Agent 输出最终台本时容易出现：

- `角色名` 占位污染。
- `speaker|台词` 残留进入正文。
- 旁白和对白重复。
- 角色表把污染 speaker 统计为正式角色。

建议改成分层协议。

### 4.2 Quote Attribution Agent

输入应是结构化 quote item，而不是整章自由文本：

```json
{
  "quoteId": "q012",
  "text": "宁默，有人来看你！",
  "leftContext": "肯定有破局的办法。就在这时，监牢中又响起一个狱卒的声音",
  "rightContext": "随后走廊尽头传来了脚步声",
  "speakerCandidates": ["狱卒", "宁默"],
  "chapterKnownRoles": ["宁默", "王大山", "狱卒", "老犯人"],
  "position": { "start": 1200, "end": 1211 }
}
```

输出：

```json
{
  "quoteId": "q012",
  "speaker": "狱卒",
  "confidence": "high",
  "evidence": "左侧明确写“狱卒的声音”",
  "voiceType": "dialogue"
}
```

硬规则：

- 台词里出现某个名字，不等于该名字是 speaker。
- 不确定时输出占位，不得输出 `角色名`。
- speaker 不得包含 `|`、引号、冒号协议残留。

### 4.3 Segment Composer

由程序负责：

- 按 span 合成旁白和对白。
- quote span 从旁白中扣除。
- 保证 segment 文本互不重叠。
- 保证原文顺序不乱。
- 对白原文不经模型改写。

### 4.4 Role Registry

角色表不应由 speaker 字符串直接统计，应先进入实体注册表：

```json
{
  "entityId": "role_guard_001",
  "displayName": "狱卒",
  "aliases": ["看守", "送饭的狱卒"],
  "category": "support",
  "confidence": "high",
  "source": "quote_attribution"
}
```

占位实体：

- `未定女声A`
- `外门弟子群`
- `系统音`
- `警察A`

这些可以进入交付，但必须标记 `unresolved` 或 `functional`，不能伪装成主角。

## 5. QC 硬拦截规则

以下任一命中，应阻止“可进入制作”：

1. speaker 为 `角色名`、`未知角色`、`speaker`、空字符串。
2. speaker 含 `|`、`“`、`”`、`：`、明显协议残留。
3. dialogue text 含 `角色|台词` 结构。
4. narration segment 中仍含成对引号，且同句 quote 已作为 dialogue 输出。
5. 同一 quote 文本同时出现在 narration 与 dialogue。
6. 角色音总表出现占位污染词。
7. quote attribution 缺少 confidence / evidence。
8. 章节标题被合入第一条旁白。

## 6. 建议下一步

### Phase 1：建立样本标注集

从本报告五本样书中各选 1 章，手工标注 20-40 个 quote：

- quote text
- 正确 speaker
- evidence
- confidence
- voiceType
- 是否允许占位

### Phase 2：实现 quote span 抽取器

先由程序输出 quote items 和 narration gaps，不调用模型。

### Phase 3：实现归属 Agent

只做 speaker attribution，不做改写。

### Phase 4：实现 deterministic composer

用 span 合成 AdaptedScriptPayload，解决重复对白和协议污染。

### Phase 5：用样书做回归

每本至少保留一个测试片段：

- 《夫人请卸甲》：未知开场 + 王大山 cue
- 《你们再吹》：群体对白 + 系统音
- 《我靠出马成名了》：第一人称 + 仙家长对白
- 《谁让他莽上去的！》：西幻人名 + 后置 cue
- 《八零之福运小寡妇》：GB18030 + `【001】` 标题

## 7. 提示词设计方向

Prompt 不应再强调“请不要误判”这种抽象要求，而应围绕证据判断：

- speaker 必须来自上下文证据或占位策略。
- 每条判断必须绑定 quoteId。
- 每条判断必须说明证据类型：前置 cue、后置 cue、连续对话、场景角色、系统音、无法确认。
- 不能产出台本正文。
- 不能重写 quote text。
- 不能输出未定义字段。

这会把 Agent 从“创作台本的人”降维成“结构判断员”，而真正的台本生成交给程序合成。这样更适合处理大量风格差异很大的网文文本。
