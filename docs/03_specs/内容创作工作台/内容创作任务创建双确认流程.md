# 内容创作任务创建双确认流程

## 文档状态

- 版本：v1.3
- 状态：已定版，作为内容创作任务创建入口的业务流程基线
- 生效范围：内容创作任务大厅、创建任务页、后续 Gateway 任务创建接口

---

## 1. 核心结论

内容创作任务创建不采用“一次提交全部内容”的表单模式，而采用两个确认闸门：

1. 先确认素材。
2. 再确认产品内容和工作范围。

改动权限、改写深度和具体修改策略不放在创建阶段确认，而是在 AI 初读分析完成后进入第三个确认闸门。

这样做的目的是让用户知道自己在确认什么，也让后台可以分阶段生成任务对象和 Agent 分配结果。

---

## 2. 第一步：确认素材

用户动作：

1. 上传原始文本文件。
2. 或粘贴短文本试跑。
3. 或从已有文档中选择素材。

系统展示：

1. 文件名、文件类型、文本类型、字数、章节识别结果。
2. 是否适合当前内容制作目标。
3. 预分配的基础 Agent，例如文件解析 Agent、内容识别 Agent、作品分析 Agent。

用户确认后的后台链路：

1. 保存原始文件为 `RawAsset`。
2. 抽取文本、清洗格式、统一编码。
3. 保存系统标准文本为 `SourceDocument`。
4. 切章节、切段落、建立轻量索引，生成 `SourceProfile`。
5. 调用 `task.intake_planner@1.0` 任务安排初步分析 Agent。
6. 生成 `IntakeReport`、`TaskDraft`、`AgentPreAllocation` 和 `IntakeWarnings`。
7. 回填第 2 步任务详细规划面板。

用户确认后生成的核心对象：

1. `SourceDocument`
2. `SourceProfile`
3. `IntakeReport`
4. `TaskDraft`
5. `AgentPreAllocation`
6. `IntakeWarnings`

第一步确认不会触发正式改写，也不会进入文本改编 Agent。

第一步必须完成素材归属判断：

1. 判断文本属于小说、论文、演讲稿、剧本、课程稿、公众号文章或其他类型。
2. 判断当前文本具备哪些结构，例如章节、段落、标题、对白、引用、论点。
3. 生成适配的候选产品方向。
4. 生成不建议的产品方向，并说明原因。
5. 第二步只能展示与素材归属匹配的候选方向，不能展示全量模板。

---

## 3. 第二步：确认产品内容和工作范围

用户动作：

1. 确认目标产物，例如多人演播有声书、广播剧、短剧脚本、只做作品分析。
2. 确认处理范围，例如第 1 章、全文、自定义章节、指定段落。
3. 可选补充目标或范围说明，例如“先看第 1 章前半段”。

这一步不选择改动权限，不决定是否重写剧情，也不选择轻度润色、重度改写等策略。

系统展示：

1. AI 初步判断，例如素材类型、章节结构、推荐目标和风险提示。
2. 推荐目标和范围，例如推荐先处理哪一章、适合做成什么产物。
3. 与素材归属匹配的候选产品方向。
4. 不建议方向及原因。
5. 结构化任务摘要。
6. 即将进入的 AI 初读分析 Agent。
7. 哪些 Agent 只作为后续候选。

第二步边界：

1. 如果第一步识别为论文，第二步不应展示多人演播有声书、广播剧等小说类方向。
2. 如果第一步识别为小说，第二步可以展示多人演播有声书、广播剧、小说润色、作品分析等方向。
3. 如果第一步识别为演讲稿，第二步应展示演讲稿润色、口播稿优化、PPT 讲稿等方向。
4. 如果用户需要强行跨类型制作，应通过“切换任务类型 / 重新生成方案”进入人工确认，而不是在默认候选里直接出现。
5. 第二步不保留自由补充大文本框，只允许用户在确认卡内部修改目标或范围。

用户确认后生成：

1. `TaskBrief`
2. `OutputTarget`
3. `WorkScope`
4. `AgentPlan`
5. `AnalysisGate`

第二步确认后，系统才可以进入业务分析 Agent。业务分析 Agent 可以耗时更久，因为用户已经确认了要分析的产品内容和工作范围。

---

## 4. 第三步：确认修改策略

第三步不属于创建任务入口，而属于 AI 初读分析完成后的执行闸门。

AI 分析完成后应展示：

1. 文本主要问题。
2. 结构风险。
3. 听感或表达风险。
4. 可修改建议。
5. 推荐修改策略。

用户在这一阶段再选择：

1. 只分析不改。
2. 轻度润色。
3. 听感改编。
4. 结构调整。
5. 剧情重写或篇章重构。

这样可以避免用户在没有看到 AI 诊断结果前盲选改动权限，也能让冲突判断更加准确。

---

## 5. 来源入口的后台归一

前端可以提供三种入口，但后台必须归一成同一种素材对象：

1. `上传文件`
   正式制作主入口，适合长文本、章节稿、docx、txt、md。
2. `粘贴试跑`
   轻量入口，适合片段测试、样章试验、用户快速验证流程。
3. `已有文档`
   项目库入口，适合复用历史解析结果、已有任务素材或用户资料库。

后续 Agent 不应关心素材来自哪个 UI 入口，只读取标准化后的 `SourceDocument` 和 `SourceProfile`。

---

## 6. 冲突处理

系统在两个闸门之间应处理冲突，而不是把冲突直接传给改写 Agent。

常见冲突：

1. 素材不是小说，但用户选择多人演播有声书。
2. 用户在第三步要求“不要改剧情”，又要求“重写结局”。
3. 用户选择前 1 章，但要求输出全书角色音表。
4. 用户上传短片段，却要求完整广播剧制作方案。

处理方式：

1. 明确提示冲突点。
2. 给出推荐修正方向。
3. 等用户确认后再进入执行。

---

## 7. UI 定版要求

创建任务页应让用户一眼看懂两个问题：

1. 我提交的素材是什么？
2. AI 接下来要替我做什么？

页面不应把 Agent 技术细节放在第一视觉层级，但需要展示“预分配”和“即将执行”，方便后台统筹理解任务走向。
