# 内容创作任务创建双确认流程

## 文档状态

- 版本：v1.1
- 状态：已定版，作为内容创作任务创建入口的业务流程基线
- 生效范围：内容创作任务大厅、创建任务页、后续 Gateway 任务创建接口

---

## 1. 核心结论

内容创作任务创建不采用“一次提交全部内容”的表单模式，而采用两个确认闸门：

1. 先确认素材。
2. 再确认执行方案。

这样做的目的是让用户知道自己在确认什么，也让后台可以分阶段生成任务对象和 Agent 分配结果。

---

## 2. 第一步：确认素材

用户动作：

1. 上传原始文本文件。
2. 或粘贴短文本试跑。
3. 或从已有文档中选择素材。

系统展示：

1. 文件名、文件类型、文本类型、字数、章节识别结果。
2. 是否适合当前内容制作目标。
3. 预分配的基础 Agent，例如文件解析 Agent、内容识别 Agent、作品分析 Agent。

用户确认后的后台链路：

1. 保存原始文件为 `RawAsset`。
2. 抽取文本、清洗格式、统一编码。
3. 保存系统标准文本为 `SourceDocument`。
4. 切章节、切段落、建立轻量索引，生成 `SourceProfile`。
5. 调用 `task.intake_planner@1.0` 任务安排初步分析 Agent。
6. 生成 `IntakeReport`、`TaskDraft`、`AgentPreAllocation` 和 `IntakeWarnings`。
7. 回填第 2 步任务详细规划面板。

用户确认后生成的核心对象：

1. `SourceDocument`
2. `SourceProfile`
3. `IntakeReport`
4. `TaskDraft`
5. `AgentPreAllocation`
6. `IntakeWarnings`

第一步确认不会触发正式改写，也不会进入文本改编 Agent。

---

## 3. 第二步：确认执行方案

用户动作：

1. 选择目标产物，例如多人演播有声书、广播剧、短剧脚本、只做作品分析。
2. 选择处理范围，例如前 1 章、全文、自定义范围。
3. 选择本轮目标，例如先分析问题、直接生成样章。
4. 填写本轮要求，例如不改剧情、提升听感、标注角色音、补充 BGM 和音效。

系统展示：

1. AI 初步判断，例如素材类型、章节结构、推荐目标和风险提示。
2. 推荐执行方案，例如推荐范围、推荐本轮目标和推荐后续 Agent。
3. 结构化任务摘要。
4. 执行边界。
5. 即将锁定的 Agent 团队结构。
6. 哪些 Agent 立即执行，哪些 Agent 只作为后续候选。

用户确认后生成：

1. `TaskBrief`
2. `OutputTarget`
3. `ExecutionBoundary`
4. `AgentPlan`
5. `ExecutionGate`

第二步确认后，系统才可以进入业务分析 Agent。业务分析 Agent 可以耗时更久，因为用户已经确认了详细执行方案。

---

## 4. 来源入口的后台归一

前端可以提供三种入口，但后台必须归一成同一种素材对象：

1. `上传文件`
   正式制作主入口，适合长文本、章节稿、docx、txt、md。
2. `粘贴试跑`
   轻量入口，适合片段测试、样章试验、用户快速验证流程。
3. `已有文档`
   项目库入口，适合复用历史解析结果、已有任务素材或用户资料库。

后续 Agent 不应关心素材来自哪个 UI 入口，只读取标准化后的 `SourceDocument` 和 `SourceProfile`。

---

## 5. 冲突处理

系统在两个闸门之间应处理冲突，而不是把冲突直接传给改写 Agent。

常见冲突：

1. 素材不是小说，但用户选择多人演播有声书。
2. 用户要求“不要改剧情”，又要求“重写结局”。
3. 用户选择前 1 章，但要求输出全书角色音表。
4. 用户上传短片段，却要求完整广播剧制作方案。

处理方式：

1. 明确提示冲突点。
2. 给出推荐修正方向。
3. 等用户确认后再进入执行。

---

## 6. UI 定版要求

创建任务页应让用户一眼看懂两个问题：

1. 我提交的素材是什么？
2. AI 接下来要替我做什么？

页面不应把 Agent 技术细节放在第一视觉层级，但需要展示“预分配”和“即将执行”，方便后台统筹理解任务走向。
