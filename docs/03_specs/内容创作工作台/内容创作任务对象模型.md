# 内容创作任务对象模型

## 文档状态

- 版本：v1.1
- 状态：草案定版，用于下一阶段后台业务逻辑和 Gateway schema 设计
- 目标：让创建任务 UI、Agent 调度和人工确认共享同一套对象语言

---

## 1. 对象总览

内容创作任务至少包含以下核心对象：

1. `RawAsset`
   用户提交的原始文件或原始文本。
2. `SourceDocument`
   用户提交的原始素材。
3. `SourceProfile`
   系统对素材的解析结果。
4. `IntakeReport`
   任务安排 Agent 的轻量分析报告。
5. `TaskDraft`
   第二步规划前的任务草案。
6. `TaskBrief`
   用户本轮任务要求的结构化摘要。
7. `OutputTarget`
   用户希望生成的目标产物。
8. `ExecutionBoundary`
   本轮可做和不可做的边界。
9. `AgentPreAllocation`
   第一步确认后生成的 Agent 预分配。
10. `AgentPlan`
   第二步确认后锁定的 Agent 团队结构。
11. `ExecutionGate`
   人工确认闸门。

---

## 2. RawAsset

用于描述用户提交的原始文件或原始文本。

建议字段：

1. `asset_id`
2. `origin`
3. `original_name`
4. `storage_uri`
5. `file_hash`
6. `mime_type`
7. `size_bytes`
8. `created_at`

`RawAsset` 只保存原始输入和追溯信息，不直接提供给后续创作 Agent 使用。

---

## 3. SourceDocument

用于描述原始素材来源。

建议字段：

1. `source_id`
2. `source_type`
3. `origin`
4. `file_name`
5. `mime_type`
6. `text_digest`
7. `created_at`

`origin` 可选值：

1. `upload`
2. `paste`
3. `library`

---

## 4. SourceProfile

用于描述素材解析结果。

建议字段：

1. `source_id`
2. `content_type`
3. `chapter_count`
4. `word_count`
5. `detected_language`
6. `structure_summary`
7. `risk_flags`

示例风险：

1. 章节边界不清。
2. 文本过短。
3. 内容类型和目标产物不匹配。
4. 存在大量对白但说话人不明确。

---

## 5. IntakeReport

用于描述任务安排 Agent 的轻量判断结果。

建议字段：

1. `content_type`
2. `structure_summary`
3. `suitability`
4. `recommended_target`
5. `recommended_scope`
6. `risk_flags`
7. `summary`

---

## 6. TaskDraft

用于描述进入第二步前的任务草案。

建议字段：

1. `task_id`
2. `source_id`
3. `recommended_target`
4. `recommended_scope`
5. `recommended_goal`
6. `reason`
7. `default_requirements`

`TaskDraft` 可以被用户修改，不能直接进入正式执行。

---

## 7. TaskBrief

用于描述用户本轮真正希望 AI 执行什么。

建议字段：

1. `task_id`
2. `source_id`
3. `goal`
4. `scope`
5. `requirements`
6. `preserve_rules`
7. `notes`

`requirements` 来自标签和自由输入，但需要先被整理成结构化摘要，不能把用户原始输入无条件传给执行 Agent。

---

## 8. OutputTarget

用于描述目标产物。

建议字段：

1. `target_type`
2. `template_id`
3. `deliverables`
4. `quality_standard`

当前目标产物候选：

1. `multicast_audiobook`
2. `radio_drama`
3. `short_drama_script`
4. `analysis_only`

---

## 9. ExecutionBoundary

用于描述执行边界。

建议字段：

1. `allowed_actions`
2. `blocked_actions`
3. `must_preserve`
4. `requires_user_confirmation`

多人演播有声书默认边界：

1. 不改变主线剧情。
2. 不替换核心人物关系。
3. 可以提升口语化、听感、演播提示和角色音标注。
4. 对未定义角色音和疑似伏笔保留不确定标记。

---

## 10. AgentPreAllocation

用于描述第一步素材确认后的候选 Agent。

建议字段：

1. `task_id`
2. `candidate_agents`
3. `reason`
4. `blocked_agents`

预分配只表达“可能需要谁”，不代表已经执行。

---

## 11. AgentPlan

用于描述第二步确认后锁定的团队结构。

建议字段：

1. `task_id`
2. `team_template_id`
3. `active_agents`
4. `standby_agents`
5. `handoff_order`
6. `required_gates`

多人演播有声书默认团队模板为 `audiobook_multicast.v1`。

---

## 12. ExecutionGate

用于描述人工确认节点。

建议字段：

1. `gate_id`
2. `gate_type`
3. `status`
4. `required_by`
5. `confirmed_snapshot`

当前创建入口需要两个 gate：

1. `source_confirmation`
2. `execution_confirmation`
