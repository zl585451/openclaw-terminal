# 多人演播角色音分类标注规则

## 文档状态

- 版本：v1.0
- 状态：当前定版，可作为角色音分类标注 Agent 的默认执行基线
- 生效方式：即日起默认按本规则执行，后续结合单章样本、跨章样本和统筹使用反馈迭代
- 修订原则：先稳定分类与占位，再逐步增强跨章回绑与分配建议能力

---

## 1. 文档目的

本文档用于定义多人演播有声小说在“文本口语化改编”完成之后，对剧本中的声音主体进行分类、占位、归属状态标注和统筹接口输出的统一规则。

本文档关注的核心问题不是“谁最终来配”，而是“这段声音属于什么类型、是否已经确认、是否需要占位、后续能否回绑到正式角色”。

其核心目标如下：

1. 统一识别文本中的角色音、旁白、功能性声音和未定来源声音。
2. 为 CV 统筹和导演提供稳定的角色音分类与占位信息。
3. 在单章模式下保持保守，在跨章模式下预留回绑和升级能力。

---

## 2. 适用范围

本文档适用于以下场景：

- 对已完成口语化改编的章节进行角色音分类标注。
- 对旁白、明确对白、文件语音、未定角色音、群像声音进行统一归类。
- 为剧组统筹提供角色池、占位池和后续分配依据。
- 为演播设计 Agent 和质检 Agent 提供上游角色音结构。

本文档不适用于以下场景：

- 最终 CV 选角拍板。
- 演员档期、成本、商务分配。
- 录音导演的具体排班决策。
- 纯后期混音参数设定。

---

## 3. 总原则

### 3.1 一句话原则

**先分类，后绑定；先占位，后分配；先保守，后确认。**

### 3.2 四项核心要求

1. **不抢结论**
   当前无法确认的声音，不强行绑定到已知角色。
2. **可延展**
   输出结果必须兼容单章制作和多章联动制作。
3. **可统筹**
   标注结果必须能直接给剧组统筹看懂和使用。
4. **可回绑**
   对未来可能确认身份的声音，保留稳定占位和升级路径。

---

## 4. Agent 定位与职责边界

### 4.1 角色音分类标注 Agent 负责

1. 识别文本中的声音主体类型。
2. 判断该声音是否为明确角色、未定角色、功能性声音或旁白。
3. 为未确认声音建立稳定占位名。
4. 给出归属状态、后续回绑可能和基础统筹提示。

### 4.2 角色音分类标注 Agent 不负责

1. 改写正文内容。
2. 最终决定由哪位 CV 配音。
3. 擅自把未知声音强绑到某个正式角色。
4. 代替演播设计 Agent 输出 BGM、音效、气口设计。

### 4.3 与其他 Agent 的关系

1. 文本口语化改编 Agent 负责“改文本”。
2. 角色音分类标注 Agent 负责“定声音类别和占位”。
3. 演播设计 Agent 负责“定演法和声音呈现方式”。
4. 质检 Agent 负责“查是否合理、是否越权、是否可执行”。

---

## 5. 两种运行模式

为兼容不同制作流程，本 Agent 应支持两种模式。

### 5.1 单章模式

适用于一次只处理当前章节的情况。

规则特点：

1. 只依据当前章节上下文做判断。
2. 对未知声音采用保守策略。
3. 优先占位，不轻易绑定。
4. 允许大量输出“待确认”“可回绑”状态。

### 5.2 跨章模式

适用于可参考多章上下文的情况。

规则特点：

1. 可结合后续章节信息做身份收束。
2. 可将多个占位声音合并为同一角色候选。
3. 可输出更强的绑定建议和兼配建议。
4. 仍不得在证据不足时强行确认。

### 5.3 默认策略

如果系统运行模式未明确，默认按**单章模式**执行。

## 6. 声音分类体系

角色音分类标注 Agent 的第一任务，不是确认“是谁”，而是确认“这是什么声音”。

### 6.1 一级分类

建议统一使用以下一级分类：

1. `旁白`
2. `明确角色对白`
3. `未定来源角色音`
4. `功能性声音`
5. `群像声音`
6. `转述性语音化内容`

### 6.2 分类定义

#### 6.2.1 旁白

用于承载叙事说明、空间信息、动作信息、情绪承接。

判定标准：

1. 该句主要作用是叙事说明。
2. 不应被理解为剧中角色直接发声。
3. 不涉及可独立分配的说话主体。

#### 6.2.2 明确角色对白

指当前已能明确说话主体的对白。

判定标准：

1. 原文或上下文已明确说话人。
2. 该声音属于剧中可识别的具体角色。
3. 统筹可以直接进入角色池管理。

#### 6.2.3 未定来源角色音

指当前不能确认具体身份，但明显不适合归为旁白的声音。

适用场景：

1. 文件中浮现的语句。
2. 案卷记录的语音化内容。
3. 回忆中未明示身份的声音。
4. 后期可能处理为 OS、回响、残响的角色音。
5. 未来可能绑定为正式角色的前置信号。

#### 6.2.4 功能性声音

指有发声主体，但其存在主要服务信息传达，不一定需要当作正式角色管理。

适用场景：

1. 广播声
2. 通知声
3. 电话语音提示
4. 留言播放
5. 监控播报
6. 机械语音

#### 6.2.5 群像声音

指无法细分到个体角色的集体性发声。

适用场景：

1. 围观群众
2. 同事群体回应
3. 多人混杂议论
4. 群体惊呼

#### 6.2.6 转述性语音化内容

指文本中原本属于记录、摘抄、转述、笔记，但在演播中可能被“读出来”的内容。

适用场景：

1. 日记摘读
2. 笔记内容浮现
3. 案卷材料被翻看时的文字具象化
4. 书信或便签内容被声音化

## 7. 特殊场景处理规则

### 7.1 文件内容浮现类

对于翻看档案、笔记、日记、案卷时出现的短句，不应默认归为旁白。

建议处理为以下两类之一：

1. `未定来源角色音`
2. `转述性语音化内容`

同时附加以下状态：

1. `delivery_mode: OS候选`
2. `speaker_confirmed: false`
3. `future_binding: allowed`

### 7.2 回忆残响类

若文本呈现为记忆里响起的话语，但当前未明确说话人：

1. 不归旁白。
2. 归入 `未定来源角色音`。
3. 标为 `回忆来源候选` 或 `残响来源候选`。

### 7.3 录音、电话、广播类

应优先归入 `功能性声音`，除非后文明确其为关键角色且需要单独管理。

### 7.4 后续可回绑类

如果某段声音当前未确认，但高度可能在后文绑定到正式角色：

1. 必须单独占位。
2. 不建议和普通路人音合并。
3. `reuse_allowed` 默认应保守处理。

---

## 8. 归属状态体系

分类之后，还需要给每个声音打上归属状态。

### 8.1 推荐状态

1. `已确认`
2. `待确认`
3. `独立占位`
4. `可回绑`
5. `可兼配`
6. `暂不分配`

### 8.2 状态定义

#### 8.2.1 已确认

说话主体已明确，可直接纳入角色表。

#### 8.2.2 待确认

主体尚不明确，但已确认不是旁白。

#### 8.2.3 独立占位

当前虽然未知，但其重要性较高，应单独保留位置，避免后续混淆。

#### 8.2.4 可回绑

允许在后续剧情出现明确证据后，回绑到某个正式角色。

#### 8.2.5 可兼配

从文本层面看，可与其他边缘角色共用 CV，但最终仍由统筹决定。

#### 8.2.6 暂不分配

当前只做声音分类，不进入具体 CV 分配。

---

## 9. 占位命名规则

为避免系统过早写死角色名，建议统一使用中性占位命名。

### 9.1 推荐命名格式

1. `未知男声A`
2. `未知女声A`
3. `未定记录者A`
4. `文件语音A`
5. `广播声A`
6. `群像男1`
7. `群像女1`
8. `未定来源角色音A`

### 9.2 命名原则

1. 名称必须稳定，便于跨段追踪。
2. 名称应优先反映声音来源，而不是强行猜身份。
3. 同类来源优先连续编号。
4. 如果后续确认身份，应保留原占位与正式角色的映射关系。

### 9.3 升级原则

当满足明确证据后，允许：

1. `未定记录者A -> 周振山（已确认）`
2. `文件语音A -> 某正式角色（高置信度回绑）`

但升级前不得直接覆盖原始占位链路。

---

## 10. 统筹视角下的输出要求

本 Agent 的输出要让剧组统筹直接看懂，并用于前期角色池整理。

### 10.1 统筹最关心的信息

1. 这是不是一个正式角色音。
2. 如果不是正式角色音，是否需要独立占位。
3. 这类声音后面会不会变成重要角色。
4. 是否建议单独找 CV。
5. 是否暂时不要分配。

### 10.2 对统筹的建议输出

每个声音主体建议至少输出：

1. 分类结果
2. 当前确认状态
3. 是否占位
4. 是否可回绑
5. 是否建议独立配音
6. 是否可兼配
7. 首次出现位置

---

## 11. 推荐字段结构

### 11.1 角色池级字段

建议输出：

- `voice_tag`
- `voice_category`
- `speaker_confirmed`
- `status`
- `first_appearance`
- `bind_candidate`
- `bind_confidence`
- `independent_cast_recommended`
- `reuse_allowed`
- `notes`

### 11.2 行级字段

建议输出：

- `speaker`
- `text`
- `voice_category`
- `source_type`
- `speaker_confirmed`
- `casting_status`
- `future_binding`
- `delivery_mode`

### 11.3 推荐示例

```yaml
voice_registry:
  - voice_tag: 未定记录者A
    voice_category: 未定来源角色音
    speaker_confirmed: false
    status: 独立占位
    first_appearance: 第1章-笔记翻阅段
    bind_candidate: null
    bind_confidence: 0.18
    independent_cast_recommended: true
    reuse_allowed: false
    notes:
      - 文件内容浮现类声音
      - 后续可能回绑为关键角色

lines:
  - speaker: 未定记录者A
    text: 老马说，别查了。
    voice_category: 未定来源角色音
    source_type: 案卷记录语音化
    speaker_confirmed: false
    casting_status: 待确认
    future_binding: allowed
    delivery_mode: OS候选
```

## 12. 单章模式下的判定策略

### 12.1 保守优先

单章模式中，默认遵循以下策略：

1. 能不确认就先不确认。
2. 能占位就先占位。
3. 能不并轨就先不并轨。
4. 对潜在关键声音保持独立。

### 12.2 打标优先级

建议优先判断：

1. 是否旁白
2. 是否明确角色对白
3. 是否功能性声音
4. 是否未定来源角色音
5. 是否需要独立占位

---

## 13. 跨章模式下的升级策略

### 13.1 可升级内容

跨章模式中，可对以下内容做升级：

1. 将多个占位音合并为同一来源候选。
2. 将未定来源角色音升级为明确角色。
3. 提升绑定置信度。
4. 给出更强的统筹分配建议。

### 13.2 仍需保守的情况

即使跨章模式，也不得在以下情况下强行升级：

1. 证据链不闭合。
2. 存在多个合理候选。
3. 只是语气相似，但缺少剧情锚点。
4. 可能影响后续悬疑结构。

---

## 14. 与演播设计 Agent 的衔接

角色音分类标注结果将直接影响演播设计层。

### 14.1 可传递的关键字段

1. `voice_category`
2. `speaker_confirmed`
3. `future_binding`
4. `delivery_mode`
5. `independent_cast_recommended`

### 14.2 衔接原则

1. 演播设计 Agent 不应重新发明角色音分类。
2. 对 `未定来源角色音`，演播设计层可做 `OS候选`、`回响候选`、`非现场声候选`。
3. 对 `功能性声音`，演播设计层应偏功能呈现，不做重角色化处理。

---

## 15. 与质检 Agent 的衔接

质检 Agent 需要重点检查以下内容：

1. 是否把未知声音误归为旁白。
2. 是否把未知声音强绑给已知角色。
3. 是否遗漏应独立占位的关键声音。
4. 是否把功能性声音误升格为正式角色。
5. 是否缺少对统筹有用的状态信息。

---

## 16. 一句话执行准则

如果需要把本规则压缩成 Agent 执行口令，可使用以下版本：

**对口语化改编后的文本进行声音主体分类；优先区分旁白、明确角色对白、未定来源角色音、功能性声音、群像声音和转述性语音化内容；对当前无法确认的声音采用保守占位策略，不强行绑定角色，并输出可供剧组统筹使用的确认状态、占位信息和回绑可能。**

---

## 17. 当前定版使用建议

在系统初期阶段，建议将本规则作为角色音分类标注层的统一基线。

执行时遵循以下策略：

1. 先跑单章模式，稳定分类和占位。
2. 暂不让 Agent 直接决定最终 CV 分配。
3. 把跨章回绑作为后续增强能力，而不是 v1 的硬依赖。
4. 对所有“文件语音”“记录浮现”“未明示来源”的内容统一进入保守池。
