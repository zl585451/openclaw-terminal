# OCT 接入 OmniRoute 的瘦身兼容总计划

## 1. 计划目标

这次瘦身的目标不是重写 OCT，也不是把本地能力全部迁走。

目标只有一件事：

- 让 `OCT` 不再自己承担“模型网关”职责
- 让 `OmniRoute` 接管模型连接、路由、fallback、压缩、协议兼容
- 让 `OCT` 继续保留产品本体、本地工具、本地记忆编排、任务编排和桌面宿主能力

最终效果是：

- `OCT` 更轻
- 模型接入更统一
- 切模型、换账号、做 fallback 不再改 OCT 主链路
- 后续删除重复网关逻辑时有明确顺序，不会误删核心能力

---

## 2. 最终目标状态

目标调用链应收敛为：

`OCT -> OmniRoute -> 具体模型提供商`

而不是继续维持：

`OCT -> 本地 provider/fallback/router -> 具体模型提供商`

在目标状态下：

- `OCT` 只决定当前请求属于哪种逻辑能力
- `OmniRoute` 决定最终落到哪个模型、哪个账号、哪个备用链路
- 本地工具实际执行仍在 `OCT`
- 本地记忆编排与任务编排仍在 `OCT`

在最终用户配置形态下：

- 普通用户只配置 `OmniRoute Base URL`
- 普通用户只配置 `OmniRoute API Key`
- 如有必要，只额外暴露极少量逻辑能力档位，例如 `标准 / 高质量 / 工具优先`
- 普通用户界面不再暴露 provider / model / baseUrl 级别的接入配置
- 上游模型选择、切换、备用和压缩策略统一由 `OmniRoute` 负责

---

## 3. 职责边界

### 3.1 OmniRoute 负责

- 模型提供商连接
- API Key / 账号管理
- 模型路由与组合策略
- fallback / 熔断 / 通道切换
- 上下文压缩
- 不同厂商协议翻译
- 统一模型出口与模型列表

### 3.2 OCT 保留

- UI 界面
- Electron 桌面宿主
- WebSocket / HTTP 传输层
- 本地工具执行环境
- tool loop
- tool 参数清洗与伪工具拦截
- 本地记忆编排与注入
- 本地任务编排与多 Agent 流程控制

### 3.3 本次明确不迁移

- 本地工具执行
- 本地记忆编排
- script adapter / task orchestration
- Electron 主进程能力
- 前三包内不做大规模 UI 重写

### 3.4 最终设置页目标

后续设置页必须收敛到下面这个目标状态：

#### 普通用户可见

- `OmniRoute Base URL`
- `OmniRoute API Key`
- 极少量模式开关或逻辑能力预设
- 本地工具权限相关设置
- 记忆与数据相关设置

#### 不再作为普通用户主配置暴露

- provider 下拉
- 手动模型 ID 输入
- 各家厂商 API Key
- 各家厂商 Base URL
- 主对话一套、工具 AI 一套的分裂式模型接入面板

#### 兼容期处理方式

- 旧 provider / model / baseUrl 设置先保留为兼容项
- 兼容项退出主路径，不再作为普通用户推荐配置
- 如确有必要，仅保留在开发者模式或兼容模式下

---

## 4. 迁移原则

1. 先并联，后切换，最后删旧
2. 先切聊天，再切规划，再切工具安全通道
3. 先验证真实使用，再删重复代码
4. 删的是重复网关逻辑，不是 OCT 核心能力
5. 每个施工包必须独立可验收、可回滚、可停在中间态

---

## 5. 统一能力模型

后续所有施工包都围绕这三条逻辑能力展开：

- `oct-chat`：普通聊天与轻量交互
- `oct-plan`：规划、总结、整理、script adapter 类非工具主导任务
- `oct-tool-safe`：需要模型参与工具决策，但工具仍在本地执行的安全通道

迁移完成后，这三条逻辑能力不再在 OCT 内部展开为物理 provider 候选，而是映射到外部 OmniRoute 的 alias / combo / model name。

---

## 6. 五个施工包

本计划控制为 5 个施工包，不再继续拆散。

### 施工包 1：外部 OmniRoute 接入基线

**阶段目标**

让 OCT 具备连接外部 OmniRoute 的能力，但不替换旧链路。

**本包应该完成什么**

- 增加外部 OmniRoute 基础配置入口
- 建立统一外部网关适配器
- 保留旧链路，允许双路共存
- 做最小连通性验证与错误提示

**本包不应该做什么**

- 不切主聊天
- 不改本地工具系统
- 不删旧 provider/fallback 代码

**本包验收重点**

- OCT 能连到外部 OmniRoute
- 旧链路还能工作
- 出问题能快速切回旧模式

---

### 施工包 2：聊天与规划链路切换

**阶段目标**

把 `oct-chat` 和 `oct-plan` 的模型出口切到 OmniRoute。

**本包应该完成什么**

- 普通聊天走外部 OmniRoute
- 规划 / 总结 / script adapter 相关模型请求走外部 OmniRoute
- OCT 只传逻辑能力，不再本地选择物理模型
- 保持原有业务行为和用户入口不变

**本包不应该做什么**

- 不动本地工具执行
- 不动 tool loop
- 不删旧链路，只做兼容保留

**本包验收重点**

- 普通聊天稳定
- 规划类任务稳定
- 老用户主要流程不变

---

### 施工包 3：工具安全通道切换

**阶段目标**

让 `oct-tool-safe` 的模型出口走 OmniRoute，但工具执行闭环仍留在 OCT 本地。

**本包应该完成什么**

- 工具安全通道的模型请求改走外部 OmniRoute
- 本地 tool loop / tool adapter / 伪工具拦截继续保留
- 明确“模型决定调用工具”和“工具实际执行”之间的边界

**本包不应该做什么**

- 不把工具系统迁成依赖 OmniRoute MCP
- 不迁走本地工具执行权限控制
- 不动本地记忆编排

**本包验收重点**

- 工具调用场景可用
- 伪工具输出仍被本地拦截
- 本地执行权限边界未被削弱

---

### 施工包 4：设置、运维与兼容收口

**阶段目标**

让新旧模式共存期间有清晰的配置、状态展示和切换控制。

**本包应该完成什么**

- 设置页收口为“外部 OmniRoute 模式”和“旧兼容模式”
- 运维/状态面板明确显示当前走哪条链路
- 错误提示、连通性检查、回退入口可见
- 历史 provider/model 配置开始降级为兼容项，而不是主配置
- 普通用户主设置收口为 `OmniRoute Base URL + OmniRoute API Key + 极少量模式开关`

**本包不应该做什么**

- 不做大规模 UI 重写
- 不立刻删除所有旧配置字段
- 不提前清理仍在兼容期内的旧逻辑

**本包验收重点**

- 用户能看懂当前模式
- 用户能完成切换与回退
- 兼容期配置不混乱

---

### 施工包 5：重复网关逻辑清理

**阶段目标**

在前四包跑稳后，删除 OCT 内部重复的模型网关能力，让瘦身真正完成。

**本包应该完成什么**

- 清理本地 provider 凭证解析
- 清理本地物理候选 fallback
- 清理本地模型路由与压缩重复逻辑
- 普通用户设置页移除 provider / model / baseUrl 级面板
- 只保留 `OmniRoute Base URL + OmniRoute API Key` 作为默认 AI 接入配置
- 如仍需少量兼容字段，仅允许进入开发者模式或兼容模式

**本包不应该做什么**

- 不删本地工具系统
- 不删本地记忆编排
- 不删任务编排
- 不删 Electron / UI / transport 主体

**本包验收重点**

- 删除的是重复网关逻辑，不是产品核心能力
- 主流程全部仍可工作
- 结构比迁移前明显更轻

---

后续每个施工包单独写施工包文档时，必须包含下面这些部分，不能再写成研究报告：

1. 阶段目标
2. 前置条件

4. 禁止修改
5. 执行步骤
6. 验收标准
7. 测试要求
8. 回滚方式
9. 完成后简报格式

每个施工包都必须是一次性交给执行 AI 完成的完整交付物，不拆成很多小轮次。

---

## 8. 兼容策略

整个迁移期间必须保持：

- 新旧链路可切换
- 新链路有问题时能快速回退
- 旧逻辑先保留，直到新链路稳定
- 兼容期内不强制删除旧配置，但旧配置必须逐步退出普通用户主界面
- 用户不需要一次性理解所有迁移细节

建议的上线节奏：

1. 内部连通
2. 小范围真实使用
3. 主流程切换
4. 工具场景切换
5. 稳定观察
6. 清理旧逻辑

---

## 9. 删除条件

只有满足下面条件，才允许进入施工包 5：

- 外部 OmniRoute 已稳定承担聊天链路
- 外部 OmniRoute 已稳定承担规划链路
- 工具安全通道已经跑通
- 本地工具执行闭环没有被削弱
- 设置页和状态面板足以支撑新模式
- 普通用户已经可以只用 `OmniRoute Base URL + OmniRoute API Key` 完成主流程配置
- 已验证回滚路径真实可用

---

## 10. 风险与回滚

### 主要风险

- 外部 OmniRoute 接入后，聊天质量或稳定性下降
- 工具场景在边界处出现偏差
- 新旧配置同时存在时，用户容易混淆
- 删除旧逻辑过早，导致无法快速回退

### 回滚原则

- 每个施工包都必须能回到上一阶段稳定状态
- 只要主流程验证不通过，就不进入下一包
- 没有完成真实使用验证之前，不删除旧链路
